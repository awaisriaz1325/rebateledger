# ADR 0017 — v1.1 feature scope and money rules

Status: accepted (founder, 2026-11-13)

## Context
After market research the founder approved building all six v1.1 features in
`docs/PHASES-v1.1.md` (Phases 12–17) and answered the questions that affect money.

## Decisions
1. **Scope.** Phases 12–17 are approved and change `docs/SPEC.md` as listed in the plan.
   SPEC §14 is unchanged in spirit: no live ERP integrations, no general-ledger posting
   (a downloadable journal file is not posting), no supplier portal, no AI.
2. **Accrual journal method: reversing.** Each export books the full accrued-to-date
   amount for the closing date and includes the matching reversal dated the first day of
   the next month. Journals always balance; amounts are `Decimal`, rounded half-up to
   cents per line, and the rounding difference (if any) is never silently absorbed — the
   export refuses and reports it.
3. **Buying-group stacking: counts for both.** A purchase line can count toward a
   supplier's own agreement and a buying-group program, because they are paid by
   different parties. The existing per-agreement `exclusive` stacking setting still
   applies within the same payer.
4. **SPA claim basis: book cost on the SPA.** Claim = (book cost on the SPA − SPA net
   cost) × quantity sold. If the sale line's cost differs from the SPA book cost, the line
   is `NEEDS_REVIEW` (reason `COST_MISMATCH`) and its amount is not changed.
5. **ERP presets** are best-guess header sets: a 2026-11-13 search found no public vendor
   documentation of these report layouts, and the reports are user-customisable. Each
   preset therefore lists several accepted names per field, is shown as **Unverified**, and
   is only ever *suggested* (the user confirms the mapping). A preset becomes verified only
   when a real customer export confirms it.

## Consequences
- The engine version is bumped in Phase 16; all existing golden fixtures must produce
  identical output.
- Phase 17 adds customer-identifying sales data: retention, full-export and
  data-protection docs must cover it.
