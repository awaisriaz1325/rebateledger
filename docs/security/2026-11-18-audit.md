# Security audit and penetration test (2026-11-18)

Scope: the whole repository (backend, frontend, production deployment files) at commit f4f8d33.
The test was run by the team against a **local** stack only (loopback ports, local Postgres and
Redis). No production system, cloud service or third party was tested. This is an internal review,
not an independent penetration test or certification.

## Method
1. **Code sweeps** (whole backend): SQL built from strings, outbound network calls, shell and
   deserialization calls, file paths from input, logging of sensitive fields, template escaping,
   PDF network access, email header handling.
2. **Design review**: authentication (passwords, MFA, sessions, CSRF, rate limits, reset and
   invite tokens), authorization (permission per route, tenant isolation, RLS), uploads,
   exports, frontend CSP and headers, redirects, production compose and images.
3. **Dynamic tests against the running app** (`backend/tests/api/test_pentest.py`, kept as
   regression tests): tenant A uses tenant B's ids in request **bodies and query strings** (the
   existing route-table matrix already covers ids in paths), session replay after logout,
   CSRF without token, with a foreign Origin and with another session's token, a half-signed-in
   (pending MFA) session, password-reset account enumeration.
4. **Black-box probe of a live API server** on 127.0.0.1: headers on errors, error bodies,
   unknown methods, malformed and oversized bodies, Origin-less login, request-id injection,
   login brute force per IP and per email, spoofed `X-Forwarded-For`.
5. **Scanners**: `make sast` (bandit), `make secrets` (gitleaks, full history), `make audit`.
6. **Production image run** with the new hardening (read-only root, no capabilities,
   no-new-privileges), rendering a PDF inside it.

## Findings

| # | Finding | Severity | Status |
|---|---|---|---|
| 1 | Open redirect after sign-in: `/login?next=/%09/evil.example` passed the check; browsers strip the tab, giving `//evil.example` | Medium | Fixed (`frontend/lib/forms.ts`, tests in `lib/forms.test.ts`) |
| 2 | `/api/openapi.json` (the full API map) was served in production; only the docs UI was off | Low | Fixed (`backend/app/main.py`, test in `test_hardening.py`) |
| 3 | Production containers ran with default Linux capabilities and a writable root filesystem | Medium (shared VM, ADR 0018) | Fixed: `cap_drop: ALL`, `no-new-privileges`, read-only root + `/tmp` tmpfs for api/worker/scheduler; caps dropped for web (`infra/prod/compose.yaml`) |
| 4 | Redis had no password (reachable only inside the stack network) | Low | Fixed: `--requirepass`, `REDIS_PASSWORD` in `prod.env` |
| 5 | Two dev-tooling advisories (picomatch ReDoS: no fixed release; minimatch: fix released 2026-11-16) fail `make audit` | Low (lint/test tooling only; patterns come from our config) | Open: founder decision |
| 6 | Expensive authenticated endpoints (report preview, statement compare, recovery audit) had no per-user rate limit | Low (paying tenants only) | Fixed: 60/min per user (`ratelimit.heavy`) on report preview, statements list/export, recovery audit + coverage, bulk-import preview, accrual preview |
| 8 | Abandoning MFA re-enrollment (after a recovery-code sign-in) cleared the confirmed authenticator, so the password alone then gave a session that could enroll a new authenticator | Medium | Fixed: the new secret is held as `pending_secret_encrypted` until confirmed (`app/services/auth.py`, migration 0014, test `test_abandoned_mfa_reenrollment_keeps_the_old_factor`) |
| 9 | Wrong MFA codes never counted toward the account lockout; signing in with the password reset the count | Low | Fixed: wrong codes and recovery codes count toward the 10-failure lockout; with MFA only a correct code clears it; a locked account's pending session accepts no code (test `test_wrong_mfa_codes_lock_the_account`) |
| 10 | The public pilot form put the submitted name into the confirmation email sent to any address (relay of attacker text) | Low | Fixed: the name is no longer in that email (`app/services/ops.py`, assertion in `test_pilot_request_reaches_inbox_and_sends_both_emails`) |
| 7 | The CSS footer of PDFs contains the organization name; HTML escaping prevents breaking out, a trailing backslash can only garble that footer | Info | Accepted |

## What held (no change needed)
- No SQL from user input: the only f-string SQL is migration helpers with constant table names.
- Another tenant's ids in bodies and queries: 404 or empty everywhere tested (claims, recovery-audit
  claims, credit allocations, run scopes, assignee and contact on claims, reconciliation,
  statements, coverage, report preview, exports, agreement filters).
- Sessions: `__Host-` cookie, HttpOnly, Secure, SameSite=Lax; server-side logout; CSRF needs both
  an allowed Origin and the per-session token; pending-MFA sessions read nothing.
- Brute force: 30 login attempts per IP / 5 min and 20 per email / 15 min, MFA 10 / 5 min; a
  spoofed `X-Forwarded-For` is ignored outside the trusted proxy network.
- Password reset answers identically for known and unknown emails.
- Errors: RFC 9457 bodies, no stack traces; security headers on every response including 404/405;
  oversized bodies 413; invalid request ids replaced.
- Uploads: 50 MB / 1M rows, XLSX zip-bomb ratio and size limits, macro workbooks refused, XML via
  defusedxml; attachments only served as downloads (`application/octet-stream`, `attachment`).
- Storage keys cannot leave the storage root; export archive names are sanitized.
- Templates auto-escaped; PDF rendering cannot fetch from the network; email headers reject
  line breaks.
- Frontend: nonce-based CSP with `strict-dynamic`, HSTS, frame denial; the only raw HTML is our own
  escaped JSON-LD.
- Logs contain no emails, passwords, tokens or file contents. gitleaks: no secrets in history.

## Not covered
Load/DoS testing, the Caddy/TLS layer, GCP IAM and the bucket (not yet created), the email
provider (not chosen), browser-level testing of the web image with dropped capabilities (the
config renders; the image was not started), social engineering, and an independent third-party
test (declined, ADR 0016).
